# Authentication System Specification

## Authentication Provider Abstraction

### Requirement: Provider Abstraction
The system SHALL provide a unified authentication interface supporting multiple providers.

#### Scenario: Provider interface
- **GIVEN** the authentication system is initialized
- **WHEN** code requests authentication services
- **THEN** a consistent AuthProvider interface is available
- **AND** the interface includes login, logout, getUser, getToken, and status methods

### Requirement: Provider Selection
The system SHALL select authentication provider based on environment configuration.

#### Scenario: Select provider
- **GIVEN** environment variables are set
- **WHEN** the application initializes
- **THEN** the correct provider is selected based on VITE_USE_ANONYMOUS_AUTH
- **AND** only the necessary provider dependencies are loaded

## Anonymous Authentication

### Requirement: Anonymous User Generation
The system SHALL generate anonymous users with readable random names.

#### Scenario: Generate anonymous user
- **WHEN** anonymous authentication creates a new user
- **THEN** a username is generated from adjective + noun + number pattern
- **AND** a unique UUID is assigned as the user ID

### Requirement: Anonymous Persistence
The system SHALL persist anonymous user credentials in browser storage.

#### Scenario: Persist anonymous session
- **GIVEN** an anonymous user is created
- **WHEN** the user data is stored
- **THEN** credentials are saved to localStorage
- **AND** the same credentials are restored on page reload

#### Scenario: Clear anonymous session
- **GIVEN** an anonymous user logs out
- **WHEN** logout is triggered
- **THEN** localStorage is cleared
- **AND** the page reloads to generate a new user

## SpacetimeAuth (OIDC) Authentication

### Requirement: OIDC Configuration
The system SHALL configure OIDC provider using SpacetimeAuth endpoints.

#### Scenario: Configure OIDC
- **GIVEN** SpacetimeAuth mode is enabled
- **WHEN** the application initializes
- **THEN** OIDC authority is set to auth.spacetimedb.com
- **AND** client ID is loaded from environment variables
- **AND** redirect URI matches application origin

### Requirement: OIDC Login Flow
The system SHALL redirect users to SpacetimeAuth for authentication.

#### Scenario: Initiate login
- **GIVEN** a user is not authenticated
- **WHEN** login is triggered
- **THEN** the user is redirected to SpacetimeAuth
- **AND** the user completes authentication
- **AND** the user is redirected back with tokens

### Requirement: OIDC Token Management
The system SHALL extract user information from OIDC tokens.

#### Scenario: Parse user from token
- **GIVEN** OIDC authentication is complete
- **WHEN** user information is requested
- **THEN** user ID is extracted from sub claim
- **AND** username is extracted from preferred_username claim
- **AND** email is extracted from email claim

### Requirement: OIDC Logout Flow
The system SHALL sign out users via OIDC signout redirect.

#### Scenario: OIDC logout
- **GIVEN** a user is authenticated via SpacetimeAuth
- **WHEN** logout is triggered
- **THEN** the user is redirected to SpacetimeAuth signout endpoint
- **AND** session is terminated on the provider

## Login UI

### Requirement: Login Form Display
The system SHALL display appropriate login UI based on authentication mode.

#### Scenario: Anonymous mode login
- **GIVEN** anonymous mode is enabled
- **WHEN** the login form is displayed
- **THEN** the form shows "Enter Chat" button
- **AND** the description says "Join the chat anonymously"

#### Scenario: SpacetimeAuth mode login
- **GIVEN** SpacetimeAuth mode is enabled
- **WHEN** the login form is displayed
- **THEN** the form shows "Sign In" button
- **AND** the description says "Sign in with SpacetimeAuth to continue"
- **AND** "Powered by SpacetimeAuth" text is shown

### Requirement: Login Animation
The system SHALL display a chibi raven mascot during login.

#### Scenario: Display mascot
- **WHEN** the login form is rendered
- **THEN** a chibi raven SVG animation is displayed
- **AND** the raven features large anime eyes and cute proportions
- **AND** the color scheme matches the application theme

## Connection Management

### Requirement: SpacetimeDB Connection
The system SHALL establish authenticated connection to SpacetimeDB.

#### Scenario: Connect with token
- **GIVEN** a user is authenticated
- **WHEN** connecting to SpacetimeDB
- **THEN** the connection includes authentication token
- **AND** the token is persisted for reconnection
- **AND** the user's identity is established in SpacetimeDB

#### Scenario: Connect anonymously
- **GIVEN** anonymous mode is enabled
- **WHEN** connecting to SpacetimeDB
- **THEN** no authentication token is required
- **AND** a new identity is generated by SpacetimeDB

## Future Provider Support

### Requirement: Provider Extensibility
The system SHOULD allow adding new OAuth2 providers with minimal changes.

#### Scenario: Add new provider
- **GIVEN** configuration for a new provider (Auth0, Clerk, etc.)
- **WHEN** the provider is implemented
- **THEN** only the AuthProvider interface needs implementation
- **AND** existing code continues to work without changes
